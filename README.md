# Домашнее задание №1 — Mushroom Classification

## Датасет

[Mushroom Classification](https://www.kaggle.com/datasets/uciml/mushroom-classification) — 8124 строки, 22 категориальных признака, бинарная классификация (съедобный / ядовитый).

Выбран потому, что все признаки категориальные — это позволяет отдельно проверить гипотезы про кодирование (OHE), отбор признаков и поведение моделей на почти детерминированно разделимой задаче.

## Гипотезы

1. **OHE на все признаки не лучше SelectKBest**, потому что много лишних признаков.
2. **Удаление `veil-type` не изменит качества моделей**, потому что он константный.
3. **Признак `odor` в одиночку даст высокий accuracy (>90%)**, потому что он сильно связан с target.
4. **RandomForest и дерево решений дадут схожее качество**, потому что задача решается стабильно и ансамбль не нужен.
5. **Дерево без ограничения глубины даст качество не хуже дерева с ограничением**, потому что комбинация признаков позволяет идеально разделить классы.

## Результаты

| № | Гипотеза | Итог | Кратко |
|---|---|---|---|
| 1 | OHE vs SelectKBest | Частично | При k=5–10 SelectKBest уступает (0.9738 / 0.9850 против 1.0000), при k≥50 качество совпадает с полным набором из 112 признаков |
| 2 | Удаление `veil-type` | Подтвердилась | ROC-AUC совпадает до 4-го знака на всех трёх моделях (LogReg, Tree, RF) |
| 3 | Только `odor` | Подтвердилась | accuracy = 0.9846, ROC-AUC = 0.9870 — значительно выше порога 90% |
| 4 | RF vs Tree | Подтвердилась | 1.0000 против 0.9998, разница 0.0002 — меньше std дерева (0.0003) |
| 5 | Глубина дерева | Подтвердилась | Разрыв train-test у неограниченного дерева = 0.0000, у max_depth=3 — 0.0031. Переобучения нет |

## Почему ROC-AUC = 1.0000 у всех моделей

Не утечка данных и не баг пайплайна. Признак `odor` почти идеально разделяет классы: для 8 из 9 категорий запаха доля одного класса равна 0% или 100%. Задача становится почти детерминированной, поэтому любая модель, использующая `odor`, выходит на ROC-AUC ≈ 1.0 — это подтверждает и гипотеза 3 (accuracy = 0.9846 на одном признаке).

## Подбор гиперпараметров

GridSearch по `max_depth`/`min_samples_leaf` дал CV ROC-AUC = 1.0000 — ровно то же, что дефолтное дерево показывало до подбора. Когда задача решается идеально базовыми параметрами, подбор не может различить конфигурации.

## Методология

- Все модели собраны через `make_pipeline` (OneHotEncoder → SelectKBest → модель), утечки нет
- Пропуски в `stalk-root` (2480 строк, замаскированы как `?`) оставлены отдельной категорией
- Для категориальных признаков — Cramer's V вместо обычной корреляции
- Test использован один раз, после фиксации всех гиперпараметров
